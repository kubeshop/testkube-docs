# Basic Ragas Example

[Ragas](https://docs.ragas.io/) is an open source framework for evaluating Retrieval-Augmented Generation (RAG)
pipelines using metrics like faithfulness and response relevancy. The Workflow below evaluates a small inline
dataset of question, answer and context samples, uploads the results as an artifact and exports the scores as metrics.
You can paste this directly into the YAML of an existing or new Workflow, just make sure to update the
`name` and `namespace` for your environment if needed.

- The `spec.config` property defines a `model` [configuration parameter](/articles/test-workflows-examples-configuration)
  for the OpenAI model that Ragas uses as the judge.
- The `spec.content.files` property defines two inline files:
  - `requirements.txt` - Ragas and the LangChain packages it uses to call OpenAI.
  - `ragas_eval.py` - a script that builds a two-sample evaluation dataset and scores it with the `Faithfulness` and
    `ResponseRelevancy` metrics, using OpenAI for both the judge LLM and embeddings.
- The `spec.container` property defines the working directory, Python image, and environment variables for the
  Workflow; the `OPENAI_API_KEY` is resolved using the [credential](/articles/credential-management) expression
  so the key is never stored in the Workflow definition itself.
- The **Install and run Ragas** step installs Ragas and its LangChain dependencies and runs the evaluation. Its `cache`
  block keeps the pip download cache between executions, so later runs install the packages from the cache instead of downloading them again; see
  [Dependency Caching](/articles/test-workflows-dependency-cache).
- The **Export metrics** step runs the [`testkube-ai-metrics-parser`](https://github.com/kubeshop/testkube-ai-metrics-parser)
  image, which converts the results into a `metrics.lp` file with the mean of each Ragas metric, tagged with the model.
- The **Save results** step uploads the JSON results and the metrics file as artifacts; the `always` condition makes
  sure they are uploaded even if the evaluation fails.

After execution, the metric scores are shown in the Log Output tab, and the `ragas_results.json` file is
available under the Artifacts tab of the execution. Testkube ingests the `metrics.lp` file as
[custom metrics](/articles/custom-metrics-in-insights) under the `ragas_eval` measurement, so you can follow the
faithfulness and relevancy scores across executions in Insights.
