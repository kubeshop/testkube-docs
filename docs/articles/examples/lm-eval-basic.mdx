# Basic LM Evaluation Harness Example

The [LM Evaluation Harness](https://github.com/EleutherAI/lm-evaluation-harness) from EleutherAI is a widely used
framework for benchmarking language models against academic tasks.
The Workflow below runs a small slice of the `gsm8k` math benchmark against an OpenAI model through the
harness's API model interface, uploads the results as artifacts and exports the scores as metrics.
You can paste this directly into the YAML of an existing or new Workflow, just make sure to update the
`name` and `namespace` for your environment if needed.

- The `spec.config` property defines two [configuration parameters](/articles/test-workflows-examples-configuration):
  `model`, the OpenAI model to benchmark, and `limit`, the number of benchmark samples to run. The default of 5 keeps
  the example fast and inexpensive; raise it for a more meaningful score.
- The `spec.content.files` property defines an inline `requirements.txt` with the harness and its API support.
- The `spec.container` property defines the working directory, Python image, and environment variables for the
  Workflow; the `OPENAI_API_KEY` is resolved using the [credential](/articles/credential-management) expression
  so the key is never stored in the Workflow definition itself.
- The **Install and run lm-eval** step installs the harness and runs the `gsm8k` task. Its `cache` block keeps the pip
  download cache between executions, so later runs install the packages from the cache instead of downloading them again; see
  [Dependency Caching](/articles/test-workflows-dependency-cache).
- The **Export metrics** step runs the [`testkube-ai-metrics-parser`](https://github.com/kubeshop/testkube-ai-metrics-parser)
  image, which converts the harness results into a `metrics.lp` file with one series per task, tagged with the model.
- The **Save results** step uploads the JSON result files and the metrics file as artifacts; the `always` condition
  makes sure they are uploaded even if the benchmark fails.

After execution, the benchmark scores are shown in the Log Output tab, and the result files are available
under the Artifacts tab of the execution. Testkube ingests the `metrics.lp` file as
[custom metrics](/articles/custom-metrics-in-insights) under the `lm_eval` measurement, so you can follow the
benchmark scores of each model across executions in Insights.
